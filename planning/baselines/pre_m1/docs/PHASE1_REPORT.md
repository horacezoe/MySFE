# 第一阶段实施与试玩报告

2026年11月6日 · 构建 `phase1-20261106`

M0A/M0B 的操作、视角和移动基础已基本完成，并提前修正实际枪口遮挡与 AI 可见性。当前交付为 Windows 试玩及 Godot 源码；完整 M1、导航 AI、正式美术与 iPad 真机验收仍未完成。

## 本轮改动

| 改动 | 解决的问题 |
| --- | --- |
| `InputRouter` 统一输入快照、按钮触点和取消 | 多指相互抢控制、松手后残留动作；首次点击只捕获鼠标；默认键位显式接受所有键盘设备 |
| `CameraRig` 自由水平观察、±80°俯仰、第三人称碰撞 | 观察角度受限和相机穿过掩体；提供观察灵敏度设置 |
| `PlayerMotor` 与 `ActionState` | 独立处理走跑、跳落和蹲行；先检查净空再起身，冲刺转射击等待举枪 |
| `AimResolver` 与两种视角的 Muzzle | 从实际枪口射击；持枪点到枪口或枪口本身被挡时拒绝开火且不扣弹 |
| AI 首个命中对象检查 | 取消距玩家 1.2 米内遮挡仍视为可见的容差 |
| 靶场、HUD 锚点和菜单 | 提供安全的 5/15/40 米目标、薄墙和低顶测试区；可暂停、调灵敏度、返回营地 |

原搜打撤流程继续使用：开箱、拾取、关闭搜索、撤离与结算。搜索时暂停世界；本轮没有增加新库存体系或迁移个人进度。

## 试玩复现

1. 双击工作目录的 `试玩第一阶段.bat` 直接进入靶场；`ember-3d/试玩.bat` 则进入菜单。
2. 点击画面捕获鼠标，确认未开火；移动鼠标水平绕一圈并上下观察。按 V 切换两种视角，再分别射击 5、15、40 米靶标。
3. 在薄墙区贴近墙面，确认“枪口受阻”、弹药不减少；后退后恢复射击。
4. 蹲进低顶通道，尝试起身、跳跃；空间不足时仍保持蹲下。走出通道后站起、跳跃、落地。
5. 按住移动或开火时暂停/切走窗口，回来后确认动作停止；恢复游戏需重新按下。暂停菜单可用滑条或 ± 调整灵敏度。
6. 返回营地进入封锁区，搜索橙色箱子，拾取后关闭再打开，确认物品数量正确；前往绿色撤离区按 E，停留 5 秒完成结算。

靶场目标不会攻击，击倒即复位；换弹补充练习弹药。靶场不会写入仓库奖励。

## 已执行验证

- `tests/test_foundation.gd`：43/43 通过，覆盖速度、跳落、低顶起身、俯仰、相机碰撞、两种视角 5/15/40 米命中、薄墙枪口遮挡及 AI 视线。
- `tests/test_game.gd`：54/54 通过，覆盖真实场景枪械、无损靶场、重复进入、暂停装填、输入取消和三轮搜索—拾取—撤离。
- `tests/test_input_router.gd`：验证首次鼠标捕获、观察增量、多指归属、按键边沿、释放/取消和上下文切换；49/49 通过，包含真实设备编号、虚拟键盘和同一帧按下再松开的短点击。
- 三指整合测试使用 `Viewport.push_input` 同时注入移动、观察、开火，并检查按钮外松手和失焦释放。它是模拟触屏测试，不是 iPad 真机验收。

最终聚合结果为 **3/3 套件、146/146 项检查通过**（49 项输入、43 项物理基础、54 项场景与布局）。布局覆盖 16:9、4:3、16:10；真实 Windows 窗口已检查主菜单、靶场和双视角按钮。

`tests/run_all.gd` 聚合执行这些套件，失败返回非零退出码。原 `smoke.gd`、`test_hit.gd`、`test_movement.gd` 保留为对应搜索、命中、移动套件的兼容入口。

## 存档与回退

场景测试通过 `test_mode=true` 禁止个人存档读取和写入；本轮未迁移 `progress` 或改变存档格式。正常封锁区试玩仍按旧规则保存财富和成功撤离次数。

迁移前六个源码/配置文件保存在 `planning/baselines/pre_m0/`。需要回退时先退出游戏并备份当前工程，再将该目录中的同名文件复制回 `ember-3d/`；原入口不引用新增模块。不要覆盖或删除个人 `user://` 存档。

## 已知限制与下一步

- 未在 iPad 安装、操作或长时间运行；签名交付、屏幕安全区、触感和持续性能仍待验证。
- 人物和枪械仍是程序化模型；蹲下视觉仍用缩放，尚无真实骨骼动画、完整装填动作或 ADS 开镜。
- AI 仍采用原型距离追击和直接伤害逻辑，本轮只收紧视线遮挡；导航、感知记忆和共享射击流程尚未实现。
- `AimResolver` 只解决本轮瞄准基础，尚无头胸命中区、护甲、完整散布及伤害衰减。物品事务、仓库、完整存档恢复继续按技术设计推进。
- 当前灵敏度为会话设置，未提供可保存的自定义触控布局；搜索长内容滚动与更多屏幕比例仍需完善。

下一轮先完成单把武器的动作与命中规则，再加入能绕障、受遮挡约束的单种 AI；详细顺序见[开发技术设计](TECHNICAL_DESIGN.md)。

实现查询时参考了 Godot 官方 [PhysicsDirectSpaceState3D](https://docs.godotengine.org/en/stable/classes/class_physicsdirectspacestate3d.html) 与 [InputEventScreenTouch](https://docs.godotengine.org/en/stable/classes/class_inputeventscreentouch.html)；最终行为以锁定引擎的实际回归结果为准。
