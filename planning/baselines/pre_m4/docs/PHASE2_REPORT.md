# 第二阶段实施与试玩报告

2026年11月6日 · 构建 `phase2-20261106`

本轮完成技术设计中 M1A/M1B 的首轮可玩范围：单把枪的统一命中与伤害、简化护甲，以及单种守卫的感知、记忆、巡逻、搜索和静态地图绕障。新增不影响仓库的双守卫演练，保留普通搜打撤与静态靶场。当前交付仍为 Windows 试玩和 Godot 源码。

## 枪械与伤害

| 实现 | 运行规则 |
| --- | --- |
| `WeaponController` | 玩家与 AI 共用弹匣、备弹、射速、装填和开火接受规则；拒绝开火不扣弹，装填完成才转移弹药 |
| `CombatResolver` | 从有效枪口发出最近命中射线；WorldSolid 和 DamageHitbox 共同参与，排除自身，ActorBody 不重复结算伤害 |
| `HealthState` | 唯一持有生命、头盔与背心耐久；头部、躯干和四肢倍率不同，四肢不被头盔或背心保护 |
| 配置资源 | 步枪与护甲参数存于 `data/weapons/*.tres`、`data/armor/*.tres`，独立随机源控制射击散布 |
| 瞄准与姿态 | 右键按住、X 或触屏按钮切换瞄准；视野与散布收窄，移动和空中增加散布，蹲下提高稳定性 |
| 治疗 | 2.2 秒完成才扣药回血；治疗期间慢速移动，开火中断且保留药包，不能同时装填 |
| 反馈 | 命中部位及实际生命/护甲损失、受击提示、墙面火花、曳光、枪口火光和有并发上限的敌人空间枪声 |

`game.gd` 的旧 `hp`、`ammo`、`reserve`、`fire_delay`、`reload_time` 属性只转发到运行模块，避免新旧逻辑各改一份状态。守卫不再按距离直接扣玩家生命，而是经过同一个枪械和射线结算流程。命中结果使用唯一 shot_id 和有界去重记录，避免重复提交同一发伤害。

枪口嵌墙或持枪点至枪口被实体墙挡住时拒绝射击，不扣弹；枪口有效、但实际弹路被前方掩体阻挡时仍接受射击并扣弹，命中最近掩体。第一、第三人称使用当前模型的 Muzzle 标记。

本轮是简化游戏规则：原始伤害等于基础值、命中倍率和距离衰减的乘积；护甲吸收量受当前部位耐久、吸收率和穿透系数限制，剩余部分扣生命。当前玩家基础伤害32、头部倍率2、四肢倍率0.65；守卫基础伤害12。最终数值以 `.tres` 资源为准，未实现真实弹道、穿透墙体或完整弹药档位系统。

## 守卫与导航

守卫状态为巡逻、调查、警觉准备、交战、搜索、返回巡逻和死亡。感知按 0.125 秒间隔采样，检查 22 米视距、100°视锥及首个有效命中对象，并累计 0.30 秒确认；确认后有 0.65 秒反应准备和有限转向速度。守卫采用短连发与停顿，需真实命中才能造成伤害。

玩家枪声只向听距内守卫传入事件发生时的位置。守卫丢失视线后调查最后已知点，搜索超时后返岗；行为模块不直接读取隐藏玩家的实时坐标。当前听觉没有复杂墙体传播，受击也会提供一次攻击来源位置。

`NavigationWorld` 为当前单层矩形场景生成静态可走多边形，墙体按 0.60 米净空扩张；`NavigationAgent3D` 在导航同步后查询路线，角色通过移动碰撞执行绕障。寻路与感知分开限频，重开演练时释放旧地图和区域。该实现不支持动态门、多层楼梯或任意地图自动烘焙，动态避障、战术掩体选择及小队协同仍未实现。

普通封锁区保留九名守卫。出生后有短部署缓冲，初始朝向避开玩家；双守卫演练另有中央 L 形掩体，遮挡两名守卫到出生点的初始视线。玩家可从两侧接近，不会在加载的第一刻直接开始受击。

## 试玩方式

入口为工作目录的 **[试玩第二阶段.bat](../../试玩第二阶段.bat)**，参数 `--combat-drill` 直接进入演练；原普通入口仍在 `ember-3d/试玩.bat`。

1. 在出生点观察中央掩体和两侧路线，按 V 切换视角。
2. 沿一侧接近守卫，观察巡逻、准备射击和交战状态；按住右键或按 X 瞄准，瞄准头部与躯干比较实际损失。
3. 在墙边开枪后移动位置，观察调查；脱离视线，观察最后位置搜索和返岗。
4. 贴墙举枪并开火，检查无效枪口不扣弹；退开射击墙面，检查有效开火会扣一发。
5. 受伤后治疗，再用开火取消；检查药包保留。暂停和恢复时，移动、瞄准、射击均需重新输入。
6. 击败两名守卫后按 Esc 重开演练；再从菜单进入普通封锁区，验证原搜索、拾取和撤离流程。

演练与静态靶场不结算仓库奖励或损失。普通封锁区保持旧存档规则，本轮未迁移个人进度。

## 回退与后续范围

第一阶段完整源码、配置和测试快照位于 `planning/baselines/pre_m1/`。需要回退时先退出游戏并备份当前工程，再将该快照复制回项目；不要覆盖或删除个人 `user://` 存档。更早原型快照继续保留在 `planning/baselines/pre_m0/`。

M2 格子库存、实物仓库、可靠结算存档和恢复尚未实现。当前世界、人物与枪械仍是原创程序化模型，蹲下和倒下是原型表现；M4 正式骨骼、完整装填动画、光学瞄具与美术替换仍待开发。本轮没有提取或复刻原游戏素材，也不宣称画面已达到原作水平。

iPad 安装签名、真实多指手感、后台恢复、安全区及持续性能都尚未验收。后续按[技术设计](TECHNICAL_DESIGN.md)推进库存与存档，再继续内容、美术和设备优化。

Windows 图形窗口已检查 4:3 布局、瞄准视野与按钮、实际开火扣弹；在演练中开枪后观察到守卫接近并完成交战。原生键盘与模拟触屏的自动验证不等于 iPad 真机测试。

导航实现参考 Godot 官方 [Using NavigationAgents](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationagents.html) 与 [NavigationMesh](https://docs.godotengine.org/en/stable/classes/class_navigationmesh.html)，并以锁定版本中的物理回归验证实际行为。
