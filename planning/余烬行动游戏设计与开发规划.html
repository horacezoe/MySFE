游戏设计规划 · 版本 1.0 · 2026年11月6日

余烬行动离线搜打撤游戏差距分析与开发规划

目标是做一款在 iPad 上独自游玩、有搜索惊喜与撤离压力、可以长期积累装备的 3D 游戏。我们参考《三角洲行动》烽火地带的体验结构，并保留可暂停、难度可调和第一第三人称切换。

规划结论：当前项目能验证基本操作与一局流程，但仍属于玩法原型。下一步应先打通稳定瞄准、公平 AI、物资管理和局外仓库，再做一块达到目标画面水准的场景。不断给现有方块加细节，不能替代角色动画、地图设计和资产制作。

供项目创作者与后续开发使用。范围以单人离线搜打撤为主，不扩展到全面战场、多人匹配或商业运营。下文所有数量、目标和优先级若未特别注明，均为本项目建议，并非原作数值。

01 当前版本真实状态

依据现有 ember-3d/game.gd、项目配置及三个测试脚本进行代码审读。下面的“已实现”只代表代码中存在对应功能，不代表已经达到成品质量；本次没有重新进行真机或整局体验测试。

模块代码中的实现实际边界
移动与视角第一第三人称切换、鼠标转向、触摸拖动、跳跃、快跑和蹲下。无开镜；俯仰约为向下37°、向上29°；蹲下通过模型纵向缩放表现。
射击一种枪；24发弹匣，120发备弹；射线命中固定25伤害；换弹、火光、弹道、命中提示。无头部倍率、护甲、不同弹药和配件；射线起点不是可见枪口。
敌人9名固定出生敌人；16米内追击，13米内满足视线检查时攻击。没有巡逻状态或导航绕障；攻击直接扣7生命，没有真实射击误差。
搜刮15个固定补给箱；每箱随机2至4件，来自8种物资；可单件或全部拾取。物资只有名称与价值；背包容量8件，无占格、重量、弃置和装备栏。
撤离每局6分钟；一个固定出口，区域内倒计时5秒；失败损失本局拾取物。没有条件撤离、多个出口、局内目标或随机事件。
局外与存档只保存财富总额与成功撤离次数。没有实物仓库、购买、出战配装、装备损失或任务进度；每局免费重置装备。
画面与声音程序化几何体、简单纹理、天空雾效、合成枪声与提示音。人物无骨骼动画；无高质量模型和材质；方向光阴影关闭，声音不是空间定位音源。
平台与验证Godot Compatibility 渲染，1280×720界面基准；已有基础搜索、视角、命中和移动测试。尚无 iPad 安装包、真机触摸验证或持续性能数据。

目前的核心缺口：撤离所得只是一个递增数字，不能改变下一次出战。因此还没有形成“这一件东西值得我冒险带走”的长期动机。

02 与原作的主要差距

官方资料可确认原作拥有小队撤离、枪械改装、装备与物品系统、干员技能和局外制造等组成部分。[1][2][3][4] 下表的体验影响与改造办法是策划判断，不是官方内部设计说明。国服和国际服资料只用于确认系统类别，不混用赛季物价和具体平衡数据。

体验层面原作参考方向我们的差距开发取舍
战前准备武器、护具、胸挂等装备与配装管理。[1][2]每局相同免费装备，几乎没有投入决策。P1：出战配装、库存扣除、失败损失。
枪械差异多枪种和配件改变武器表现。[1][3]只有一套固定参数与外形。P0：先做好一把枪，再扩充两种明显不同的武器。
搜索惊喜可搜索物品、收藏和价值回收是重要内容。[1][3]开箱立即显示文字，无未知物品揭示过程。P1：容器类别、分步揭示、稀有物提示与用途。
装备与防护存在头盔、护甲、胸挂和弹药等级等系统。[1][2]仅生命条；换装不能改变生存能力。P1：少量护具与弹药档位，建立可理解的差异。
局外成长有制造、任务、经济记录与收藏。[1][3][5]只有财富计数器，不能花钱或留存装备。P1：仓库和固定商店；制造与收藏放到P2。
撤离选择官方明确有多种撤离方式。[4]唯一固定出口、固定等待，无线路选择。P1：普通出口与一个有条件出口。
地图探索区域、通道及攻守空间存在明确差异。[5]小型平地障碍场，缺少室内外和重要地点。P1：一张原创地图，三类区域、两条以上路线。
战斗压力同时包含电脑敌人与真人小队威胁。[1]简单追击AI易造成单调或突然扣血。P0至P1：可观察、可回避、可调节的AI。
干员与战术有干员技能与战术道具。[1][5]治疗之外没有战术工具。P2：先加烟雾或诱饵，不急于做完整干员体系。
动作与视听官方产品呈现完整战术射击体验；具体资产质量需要逐项实机对照。模型拼装、动作缩放、合成音效造成明显原型感。P1开始做单一区域的模型与动画样板，验证后扩展。
移动端操作存在正式iPad产品。[1]固定坐标按钮，未测试多指协同和屏幕比例。P0：触摸输入与布局先可靠，陀螺仪等后置。

应保留的不同：离线单人、可暂停、难度可调、第三人称切换以及可选损失规则，都服务于你的需求。我们要复现搜索、战斗和撤离的体验，不必复制真人对抗压力、赛季重置和付费运营。

03 操作与战斗设计

让准星 枪口和命中结果一致

玩家说“枪械能自由指向前方”，应落实为三个条件：视角可以连续转动；模型的枪口跟随瞄准；实际命中点与准星一致且不会穿过遮挡。当前只部分满足，第三人称的模型俯仰与射线起点仍是近似实现。

  1. 统一鼠标、触摸和后续手柄的观察输入。水平连续旋转，垂直范围先试向上向下各80°；范围与灵敏度可调，避免首击捕获鼠标时误开枪。
  2. 相机射线确定目标点，实际枪口到目标点再次检查遮挡。墙贴脸、掩体边缘和近距离目标都必须验证；枪口被挡时显示提示，不能依靠偏移射线起点跳过墙面。
  3. 引入开镜瞄准。开镜改变视野、灵敏度、持枪位置与散布；先实现一种机械瞄具或红点。相机后坐力、枪械动画后坐力与回正各自调节。
  4. 第三人称使用肩后相机与防穿墙碰撞；枪械通过目标点定向，后续用骨骼和双手约束保持握枪姿态。可换肩放在基础对齐稳定之后。

把动作变成有规则的状态

建立待机、移动、快跑、蹲下、跳跃、开镜、射击、换弹、治疗和搜索状态。明确互斥关系：快跑时是否允许开火、跳跃是否打断换弹、治疗是否可取消，都要有一致反馈。建议快跑结束后有短暂举枪过程；蹲下减少移动速度，跳跃增加散布。具体数值由靶场调试，不照搬原作。

蹲下改用骨骼姿势和独立碰撞体；起身前做头顶空间检查。快跑加入可关闭的体力规则，避免默认无限快跑让绕行和负重失去意义。

战斗模型从简单但可信开始

第一批只做步枪、冲锋枪两类武器，配两个弹药档位和两个防护档位。支持头部与躯干命中区、伤害衰减、装填耗时和有限散布；护甲影响存活能力，并明确显示防护消耗。暂不扩展复杂肢体医疗或全套真实弹道。

验收：第一、第三人称分别在近、中、远三个距离测试；准星指向靶标时命中区域正确，墙后目标不可受伤。动作切换不会卡住输入、重复扣弹或免除换弹时间。

04 搜索背包与局外循环

容器中的东西要有等待和选择

区分医疗箱、工具箱、武器箱和保险柜，各自使用不同物资池。打开后先显示未知槽位，再逐件揭示图标、名称、品质、大小、重量和用途。物品在本局首次生成后固定，关闭重开不重新抽取；搜索计时和已揭示进度也要保留。

默认采用舒适模式：允许搜索时暂停。另提供标准模式：搜索时世界继续运行，并保留周围声音与受击打断。把暂停作为明确的难度选项，避免现在隐含在代码里的全局冻结。

背包应支持取舍

先用紧凑的格子背包实现拖放、旋转、堆叠、拆分、弃置和快速拾取。物品占用不同格数，提供“每格价值”辅助比较；背包重量影响快跑消耗，不能仅靠件数限制。装备栏与收集品分开，允许从敌人战利品中取枪、弹药和护具。

推荐第一批内容规模：20种左右收集品、4种容器、两种背包。这个数量是制作范围，不是原作统计。稀有物不仅卖钱，也可用于任务或解锁，避免所有物品只是同一种数字的不同标签。

建立真正的局外循环

流程为：整理仓库 → 选择配装 → 入场扣除随身物资 → 搜索与完成目标 → 撤离带回实物 → 留用、出售或交任务 → 准备下一局。免费基础套装作为破产保护，标准模式下仍需要承担携带装备的损失。

存档必须记录物品唯一ID、数量、装备耐久、配件、仓库、任务和设置，并带版本号。撤离结算只执行一次；出战扣除与成功返回形成完整事务。崩溃或切后台时优先保证不丢存档、不复制物品。

验收：装满背包再拾取不丢物品；多次点击不会重复获取；失败按所选规则清算。连续完成3局后，仓库变化、花费、收益和失败损失都能解释清楚。

05 单人 AI 与难度

原作的真人小队让风险难以预测；我们的替代方式应是有行为变化的AI与地图事件，而不是给敌人无限视野和更高伤害。当前敌人主要使用距离触发追击，必须先补感知和攻击过程。

最小敌人状态流程

巡逻 → 听到声音或看到异常 → 前往调查 → 发现玩家并警告 → 找掩体与射击 → 丢失目标后搜索 → 返回巡逻。导航负责绕过墙体；视觉必须考虑朝向、遮挡和确认时间；听觉由快跑、枪声、开门等事件触发。

开火应经过瞄准、反应延迟和散布判定，使用与玩家一致的命中与遮挡系统。第一枪前给出可感知的语音、举枪或弹道线索。丢失视野后只知道最后出现的位置，不能持续追踪玩家坐标。

建议的三种游玩预设

预设主要规则适用目的
探索敌人较少、反应较慢；允许暂停搜索；失败可保留更多收获。轻松熟悉地图和享受收集。建议初始默认。
标准搜索不停时；正常巡逻与听觉；失败损失出战装备及未保护物资。体验完整单人搜打撤循环。
挑战更主动的搜索、掩体与协同，资源更紧张。用行为变化增加难度，避免单纯堆生命和伤害。

预设内可独立调整敌人数量、反应时间、伤害、暂停搜索和失败损失。AI队友、Boss与动态敌方小队放到基础敌人稳定之后；首版不需要大量种类。

验收：隔墙不持续精确追踪；绕障有效；同一掩体能阻挡双方射击；AI攻击有预兆；玩家能通过安静移动、撤退和绕行避免一部分战斗。

06 地图人物与枪械美术

先做一张值得探索的原创地图

建议第一张地图采用“废弃货运站与维护区”主题，由外围补给区、室内仓储区和高风险控制区组成。每处高价值目标至少有两条接近路线；一条短而暴露，另一条更安全但耗时。地图大小由步行时间和遭遇频率决定，不先追求面积。

第一轮内容目标是单局约10至15分钟、三处可辨认地标、两种撤离方式，以及搜集、交付、启动设备三类简单目标。仓库屋顶、楼梯、门窗和室内外视线要先用灰盒测试；地形、植被和装饰不能掩盖不通畅的路线。

写实感需要换制作方法

目前的人物由方块和球体拼装，蹲下是缩放，持枪手臂没有骨骼约束。继续堆几何体只能缓解粗糙感。应制作或选用授权明确的角色、武器与环境模型，并统一比例、材质和动作风格。

  • 人物：一套有骨骼的角色，配待机、走跑、蹲行、跳落、受击和倒地动画。上半身瞄准与下半身移动独立混合，双手跟随枪械握持点。
  • 枪械：先做一把完整样板，包含机匣、弹匣、枪机、瞄具和枪口定位点；使用金属、塑料的粗糙度与法线贴图。换弹让弹匣真正移动，枪机和抛壳按动画事件触发。
  • 地图：模块化建筑、真实尺寸、地面材质层次、局部污渍与磨损。使用烘焙光照、接触阴影或有限实时阴影补足空间关系，按设备预算选取。
  • 声音：脚步按表面区分，远近枪声、换弹机械声、受击与室内混响提供定位。保留独立音量控制，减少重复高频提示音。

资产入库时记录来源、许可、作者、版本和性能开销。使用原创或允许使用的资源，不提取原游戏模型、地图、音效和品牌UI。参考其可读性与战术氛围即可。

样板验收：先完成一间仓库、一段室外道路、一名角色和一把枪，在第一第三人称下以统一光照审看；通过性能测试后再铺开地图。视觉目标是相对当前原型明显提升，不承诺达到商业大作的资产数量或精度。

07 当前问题与工程调整

以下为代码审读结论。标为“待复现”的内容需要专项验证，不能当作已经确认的故障。本次只记录，不修改游戏功能。

编号问题与证据处理方式
R01 已确认俯仰限制为−0.65至0.5弧度；枪口模型与射线位置不是同一节点。game.gd 561至589、645至665、701至713行。统一瞄准目标、扩大可配范围；实际枪口遮挡测试优先。
R02 已确认AI按距离追击，攻击直接扣血；没有巡逻与路径导航。671至683行。感知、导航、反应延迟和射击事件分开实现。
R03 已确认搜索开启时物理逻辑直接返回；交互只检查距离，无容器视线检查。440至455、591至592行。搜索暂停改为选项；容器交互加朝向与遮挡检测。
R04 待复现暂停未统一清空移动触摸ID；未见应用失焦、切后台统一处理。测试按住移动时暂停、来回切后台和手指移出按钮；统一取消输入。
R05 待复现关闭触摸模拟鼠标，但按钮使用普通Button，触摸事件又在_unhandled_input中分配。真机核对移动、观察、开火三指同时输入；明确GUI与手势事件归属。
R06 已确认蹲下缩放整个可见模型；起身未做头顶空间检查。633至638行。改骨骼姿势，先检测能否起身；低矮空间添加回归场景。
R07 待复现界面大量固定像素坐标，搜索内容没有滚动区域。365至423、458至475行。测试4:3与其他iPad比例、长物品名称、满背包；改锚点及滚动容器。
R08 已确认存档只有wealth与wins；战利品在结算后只转化成总价值。524至538行。建立物品实例和有版本的仓库存档，确保结算只执行一次。

保持现有 Godot 项目 逐步拆分

当前主要逻辑集中在约725行的一个脚本。按功能逐步拆成 PlayerController、CameraRig、WeaponController、Inventory、EnemyAI、RaidManager、SaveService 与 UI；将枪械、敌人、地图做成独立场景。物品和武器参数放入资源数据，避免每加一个物品都修改战斗代码。

先保留可玩的旧场景作为回归基线；每拆出一个模块就跑现有测试并补该模块的关键场景。新功能以数据与事件连接，避免改一次相机就破坏搜刮或存档。

08 分阶段开发路线

按验收结果推进，不给尚无依据的日历承诺。P0表示基础可靠性，P1表示完整可玩版本，P2表示深度扩展，P3表示规模与发布准备。美术样板可在玩法稳定后与系统开发交替推进。

阶段交付范围进入下一阶段的条件
M0 基线
P0		备份可玩版本，整理输入、相机、射击和状态；制作靶场、墙角与低矮通道测试区。瞄准与命中一致，暂停不残留输入，动作切换稳定。
M1 射击体验
P0		完整一把枪、开镜、换弹状态、命中分区与基础AI射击；鼠标和触摸参数可配。连续战斗可理解、可躲避；第一第三人称都能稳定命中。
M2 搜打撤闭环
P1		格子背包、物资用途、战前配装、实物仓库、固定商店、失败规则与基础任务。完成至少3局连续成长循环；重启不丢物品，结算不复制物品。
M3 单图内容
P1		一张原创地图、3类区域、2种出口、巡逻与调查AI；一处完成美术样板的场景。存在有意义的路线和撤离选择，安静绕行可避战，重复开局有变化。
M4 内容与表现
P2		扩到两类枪、少量附件与护具；骨骼角色、正式动画、空间音效、收集与解锁。资产风格一致，各种装备能改变玩法；保持基础性能目标。
M5 设备验收
P3		选定iPad型号和交付路径，触屏布局、画质档、后台存档、断网启动与长时间运行。目标真机完成操作、存档与性能验收后，才称为可交付的iPad版本。

依赖顺序是：输入与命中 → 武器和AI → 背包数据 → 仓库与任务 → 地图内容 → 扩充资产。iPad实机触控应在最早可部署时开始抽测，不应等所有美术完成才发现操作方案不可用。

暂缓范围

大地图群、大量枪械、完整干员技能树、载具、联机、赛季经济、拍卖行和复杂身体医疗都暂缓。先让一张地图与少量装备持续好玩，再按实际游玩反馈扩展。

09 下一轮开发任务

建议下一轮只完成M0和M1中的基础部分。每条任务都应有可演示结果，避免用“更真实”“更像原作”作为唯一完成标准。

任务具体结果验收方法
T01 输入清理统一触摸ID、鼠标捕获、暂停与失焦；捕获鼠标不误开枪。按住移动时暂停或切后台再回来，角色停住且可重新操作。
T02 瞄准修正可调俯仰和灵敏度；相机目标与真实枪口射线一致。两种视角在5、15、40米靶位与贴墙位置逐项检查。
T03 状态互斥规定快跑、跳跃、蹲下、换弹和开火关系；增加起身空间检查。低顶不能强行站起；连续切换不重复扣弹、不穿模。
T04 AI攻击过程视线确认、开火预兆、有限散布和遮挡判定。墙后不受伤；看到预兆后玩家有机会回避。
T05 容器交互修复隔墙搜箱风险；搜索暂停变成明确选项。隔墙无法开箱；切换模式后计时与敌人行为一致。
T06 靶场样板一把枪的开镜和换弹表现；保留现有命中标识。实际射击录像可见枪口、准星和目标反馈一致。

完成这轮后再决定是否进入背包与仓库重构。先保留原版脚本和存档副本；任何迁移都应可回退。

10 验收与设备测试

已有验证不能替代整局试玩

现有测试覆盖单件拾取与重开容器、第一第三人称开关、一次命中扣血，以及蹲下、跳跃落地和快跑速度。它们没有覆盖满背包、结算事务、多指输入、低顶起身、复杂遮挡、AI导航或持续性能。后续应按这些风险补场景测试，而不是仅增加重复启动测试。

  • 操作：左右移动、观察、射击同时进行；两种视角切换20次；暂停、搜索和失焦后无卡住输入。触屏按键不相互抢占。
  • 战斗：贴墙、近身、不同高度靶标都可解释命中；AI和玩家遵守相同遮挡；空弹、取消换弹与重复按键不产生额外弹药。
  • 物资：满包、重复拾取、弃置再拾取、搜索中退出、撤离按钮重复触发和读档都不丢失或复制物品。
  • 节奏：完整试玩10局，记录主动开战、被迫开战、绕行、死亡原因与退出原因；判断玩家是否能选择探索而非每局都被迫打满。
  • 离线：最终目标设备在断网后可启动、继续游戏和保存；这是发布条件，当前尚未验证。

性能目标必须绑定具体 iPad

先记录型号、芯片、内存、系统版本和交付形态。建议把连续20分钟、30帧稳定档作为最低候选目标，再评估60帧档；帧时间分别对应约33.3毫秒与16.7毫秒。它们是未来测试目标，不是当前性能承诺。记录低帧、温升、内存和存档中断情况，避免仅凭桌面显卡测试判断移动端可用。

资产预算由真机数据反推：贴图尺寸、可见角色数、材质数量、阴影距离、特效粒子和音源数量都要可配置。优先确保瞄准反馈稳定，再提高画面复杂度。iPad开发与打包路径另行决定，本轮不安装新开发环境。

完成标准

能够稳定完成出战、搜索、战斗、撤离和仓库整理；游戏过程有可理解的风险与收益；玩家能通过操作和选择改变结果。达到这些标准后，再把资源投入更多地图和武器。
