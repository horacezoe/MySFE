# 增量更新：搜索被击败的敌人

构建 `phase5-loot-20261106`。这是第五阶段之后的玩法补充，M5 的 iPad 适配计划保持不变。

## 玩法

在正常封锁区行动中，击败守卫后靠近其身体，按 **E** 或触屏 **搜索敌人** 打开物资界面。需要在 2.3 米内且没有墙体阻挡；附近同时有箱子和尸体时选择最近的可搜索目标。附近尸体会显示小型状态标识，空尸体标为已取空。

搜索每 0.7 秒揭示一件物品，搜索期间暂停世界。可以逐件转移或拾取全部已揭示物品，未揭示物品不可通过按钮或数据命令提前取得。背包容量、重量与堆叠规则沿用现有系统；放不下的部分留在尸体上。

每具尸体为 6×5 格，包含现有步枪物品、头盔和背心、剩余备弹、一件小型收集品，以及 55% 概率的一件药包。步枪保留敌人死亡时的弹匣余量，护具保留剩余耐久，损坏至零也不会自动修复。收集品及药包由对局种子和守卫身份确定，开关搜索或读档不会重抽。

拿走步枪后，尸体上的枪械模型隐藏。物资全部取走后仍可查看空容器，不补货。拾取物资随正常撤离进入仓库；没有拾取的部分在本局结束时清理。装备仍需回营地更换。

尸体与撤离区重叠时，看向尸体可以搜索，看向别处按 E 可以撤离，HUD 按钮跟随当前操作变化。满背包不会导致被尸体挡住撤离操作。

## 保存与兼容

`ProfileService.commit()` 在候选副本中从死亡快照创建 `loot_guard_00` 至 `loot_guard_08`，并将死亡、掉落物品与搜索状态一起保存，成功后才发布。保存失败暂停游戏，重试前不会发布新尸体或转移物品。创建过程自身也使用候选副本，生成失败不留下半个容器。

已创建尸体以容器及搜索记录作为持久身份，包括空容器。搜索顺序保留已转移物品的记录，防止空尸体重生战利品。源守卫必须已死亡，当前物品必须属于原搜索顺序；隐藏物品权限、重复命令和结算清理复用现有库存规则。

没有更改存档 schema 或物品定义 ID。旧存档缺少尸体容器仍可读取，首次正常检查点补齐已有死亡敌人的物资；第三阶段升级提交本身保持旧搜索数据，补齐发生在恢复对局之后。已有箱子的掉落和揭示进度保持不变。

静态靶场和双守卫演练仍不产生可带回仓库的战利品。新增独立 **敌人搜索练习** 使用临时进度，专门演示完整搜索流程，不读取或写入个人存档。
